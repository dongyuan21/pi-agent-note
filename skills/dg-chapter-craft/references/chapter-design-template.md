## 1. 本章一句话

读者看完后脑子里的认知变化（**不是主题列表**）：

> **\<旧认知 → 新认知\>。用「约定/机制 X」换「能力/灵活 Y」……**

坏例子：「这章讲了 28 个事件、注册机制、两阶段绑定。」  
好例子：「扩展系统不是魔法注入，而是在工作流关键点 emit 事件——用约定换灵活。」

## 设计文档自检（写正文前）

1. 概念空白清单完整吗？每个都有引入策略？  
2. 链路是否从触发追到最终结果？  
3. 叙事起点是否制造了需求（而非 API 目录）？  
4. 是否至少有一个真「破」点？  
5. 数据展示是否具体到字段/状态？  
6. 读者画像与叙事策略是否一致？  
7. 方法论预告是否能脱离 Pi 专有名词复述？
