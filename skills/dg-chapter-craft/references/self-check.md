# 章节自检清单

用于：设计文档完工检查、正文完工检查、审稿。

打分约定：每项 ✅ / ⚠️ / ❌。有 ❌ 不得发布；⚠️ 须在 PR/审稿意见中说明取舍。

---

## A. 三问完整性

| # | 检查项 | 结果 | 笔记 |
|---|--------|------|------|
| A1 | 章内能明确指出「是什么」的主定义或边界 |  |  |
| A2 | 「怎么做」落到可核对源码路径/符号（或实战可运行步骤） |  |  |
| A3 | 「为什么」包含至少一处反例或替代方案代价 |  |  |
| A4 | 没有整节只贴 API/事件名却不解释动机 |  |  |

---

## B. 建 → 破 → 立

| # | 检查项 | 结果 | 笔记 |
|---|--------|------|------|
| B1 | 至少 1 个完整循环；主线难点有循环 |  |  |
| B2 | 「破」是读者会问的矛盾，不是术语堆砌 |  |  |
| B3 | 「立」同时给出机制与工程动机 |  |  |
| B4 | 循环数量未导致疲劳（通常 ≤3） |  |  |

---

## C. 链路闭环

| # | 检查项 | 结果 | 笔记 |
|---|--------|------|------|
| C1 | 设计文档链路表存在且无 ❌ |  |  |
| C2 | 正文完整走通 ≥1 条主链路（触发→中转→消费→结果） |  |  |
| C3 | 事件/钩子/管道无「只报名」断链 |  |  |
| C4 | 配图节点能映射到正文步骤（若有图） |  |  |

---

## D. 可迁移方法论

| # | 检查项 | 结果 | 笔记 |
|---|--------|------|------|
| D1 | 有独立方法论/设计精华节 |  |  |
| D2 | 每条有名、有来源、有复用指引 |  |  |
| D3 | 删掉 Pi 专有名词后方法仍可复述 |  |  |
| D4 | 条目 3～5 条，无注水 |  |  |

---

## E. 叙事与衔接

| # | 检查项 | 结果 | 笔记 |
|---|--------|------|------|
| E1 | 开场制造需求或接住上章悬念 |  |  |
| E2 | 收尾回扣开场问题 |  |  |
| E3 | 「下一站」只抛接口词/问题，不剧透 |  |  |
| E4 | 概念空白均在使用前引入；类比有失效边界 |  |  |

---

## F. 工程与版本

| # | 检查项 | 结果 | 笔记 |
|---|--------|------|------|
| F1 | 章首或章末声明对照的 Pi 版本（当前工程：最新稳定版号） |  |  |
| F2 | 文末源码索引与正文引用一致 |  |  |
| F3 | 若有 Web mdx：与 md 同步策略已处理（`check:sync`） |  |  |
| F4 | 实战章：配套代码路径正确，`npm install` 后可按章运行 |  |  |
